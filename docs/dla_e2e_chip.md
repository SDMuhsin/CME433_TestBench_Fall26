# dla_e2e_chip: end-to-end G300 GAN generator ASIC (RTL)

`rtl/dla_e2e_chip.sv` runs the whole MNIST-GAN generator on chip: 64 -> 256 -> 256 -> 784 with ReLU, ReLU and Tanh. That covers bias, requant, activations, tiling and sequencing. The host sends the int8 latent `zq` plus the weights and biases, then reads back 784 int8 pixels. The result is bit-exact with `tb/data/g300_int8/g300_int8_rtl.memh`.

The pad terminals are the same 11 as `dla_engine_chip`, and the `u_dla` hierarchy is unchanged, so the 8 SRAM macro instance names are the same. The existing `dla_engine_chip` and its serial bridge are untouched.

**Status:** RTL and simulation only. No place and route has been run yet.

## Blocks
| File | Role |
|---|---|
| `rtl/dla_e2e_chip.sv` | Chip top. Pad wiring, quad IO OE, read-data mux |
| `rtl/e2e_host_qspi.v` | Serial host interface: 2FF-synchronised SCLK/CS_N/IO[3:0], command decode, quad stream, quad/1-bit readback |
| `rtl/e2e_csr.v` | ID/CTRL/STATUS registers, plus six writable 32-bit requant multipliers. Reset values come from `rtl/g300_quant_params.vh` |
| `rtl/e2e_seq.v` | Layer/tile FSM: 4-byte skid FIFO, bias double buffer, write-port arbiter, requant control, activation ping-pong in B, 16-byte pixel tail stash, HRDY/DONE |
| `rtl/e2e_requant.v` | `t = acc*Ma + b*Mb + 2^15`, `pre = t>>>16` using a shift-add multiplier (34-bit adder). Then ReLU/sat127, or clamp to +/-2^22 followed by a tanh threshold binary search. Latency is 35 clk (ReLU) or 43 clk (tanh) |
| `rtl/e2e_tanh_rom.v` | 256x15 threshold ROM, generated by `scripts/gen_e2e_tanh_rom.py`, which also proves it exact for all 32,769 LUT indices |
| `rtl/dla_engine_top.v`, `rtl/dla_controller.v` | New parameter `E2E_EXT` (default 0, which keeps the old behaviour). It adds a runtime `k_last` and a B-row read port (`b_rd_sel/addr/data`) |

## Pins
| Pad | Old role | e2e role |
|---|---|---|
| W15 `SCLK_*` | SCLK | SCLK (in) |
| W17 `CS_N_*` | CS_N | CS_N (in) |
| W16 `MOSI_*` | MOSI | IO0 (bidir) |
| W18 `MISO_*` | MISO | IO1 (bidir) |
| W19 `busy_*` | busy | IO2 (bidir) |
| W20 `done_*` | done | IO3 (bidir) |
| W21 `wb_done_*` | wb_done | HRDY (out) |

For the IO pads, `*_OE` is driven by the interface and `*_IE` is 1.

HRDY is high when no image is in flight. While streaming, it is high when the skid FIFO holds at most 1 byte. After the last stream byte it stays low until the image is done.

## Host protocol
The bus is SPI mode 0, MSB first. Every command byte is sent 1-bit on IO0.

Timing limits:
- Write and stream phases work at SCLK <= clk/4.
- Read phases need SCLK <= clk/8. Read data changes about 3 clk after a rising edge, so the host samples just before each rising edge.

| Cmd | Name | After the command byte |
|---|---|---|
| 0x02 | WR_CSR | addr8 (1b), then data bytes (1b), auto-increment |
| 0x0B | RD_CSR | addr8 (1b), 8 dummy SCLK, then data on IO1, auto-increment |
| 0x31 | START | Arms the sequencer, clears DONE/errors, resets the stream pointer |
| 0x32 | STREAM_Q | Stream bytes until CS_N rises. 2 SCLK per byte on IO[3:0], high nibble first. If CTRL.quad_en=0, it is 8 SCLK per byte on IO0. A stream can be split into any number of frames |
| 0x6B | RD_PIX_Q | addr16 quad (4 SCLK), 4 dummy SCLK, then pixels 2 SCLK per byte, auto-increment |
| 0x03 | RD_PIX | addr16 (1b), 8 dummy, then data on IO1 |
| 0x10 / 0x11 | DBG_WR_A / DBG_WR_B | addr16 (1b), then data bytes (1b). Raw A/B write (A: row*256+k, B: k*4+col) |
| 0x12 | DBG_START | k_last (1b). Raw DLA run |
| 0x13 | DBG_RD_C | byte addr16 (1b), 8 dummy, then data on IO1. C word is a[5:2], byte is a[1:0] (LE), byte 3 is the sign extension |

The DBG_* commands are ignored while an image is in flight. Any other command byte sets STATUS.err_cmd.

**CSR map** (multi-byte fields are little endian):

| Addr | Field |
|---|---|
| 0x00 | ID = 0xE2 |
| 0x01 | CTRL: [0] soft_reset_seq, [1] pe_col_gate_en (reserved), [2] quad_en (reset 1) |
| 0x02 | STATUS: [0] busy, [1] done, [2] hrdy, [3] err_cmd, [4] err_overflow, [6:5] layer |
| 0x03-0x05 | Stream byte count (19 b) |
| 0x06 | Tile |
| 0x10 / 0x14 / 0x18 / 0x1C / 0x20 / 0x24 | MA0 / MB0 / MA2 / MB2 / MW4 / MB4 (32 b; reset = golden constants) |

**Per image:**
1. Optionally WR_CSR the 6 multipliers. They are calibrated per latent by `scripts/gen_g300_int8_assets.py`. The reset values match the committed latent.
2. Send START.
3. Send STREAM_Q with 283,984 B, checking HRDY before every byte. The layout is:
   - `zq[64]`;
   - L0: 64 tiles x {4 bias, 4 x 64 W};
   - L2: 64 tiles x {4 bias, 4 x 256 W};
   - L4: 196 tiles x {4 bias, 4 x 256 W}.

   Weight rows are in `G300_*_weight.memh` order.
4. Wait for HRDY high, or for STATUS.done.
5. Send RD_PIX_Q from address 0 and read 784 B. Pixels are int8: `pix = tanh_pixel - 128`.

Read the pixels before the next START. Pixels are stored in B columns 1-3 plus a 16-byte flip-flop stash, and the next image overwrites column 1.

## Memory use
B column 0 and column 1 form an activation ping-pong:
- zq goes to col0, and L0 writes h0 to col1.
- L2 writes h2 to col0.
- L4 writes pixel p<768 to col(1+p/256)[p%256]. Pixels p>=768 go to the stash.

A holds one tile of weights (4 rows). No SRAM macros were added.

## Running the testbenches (from the repo root)
```bash
# unit tests
python3 scripts/gen_e2e_vectors.py sim/results            # 1,296 golden + corner + 40k random tuples
iverilog -g2012 -s e2e_requant_tb -o sim/results/e2e_requant_tb.vvp rtl/e2e_requant.v rtl/e2e_tanh_rom.v tb/e2e_requant_tb.sv
vvp sim/results/e2e_requant_tb.vvp +VEC=sim/results/e2e_requant_vectors.memh
iverilog -g2012 -s e2e_tanh_rom_tb -o sim/results/e2e_tanh_rom_tb.vvp rtl/e2e_requant.v rtl/e2e_tanh_rom.v tb/e2e_tanh_rom_tb.sv
vvp sim/results/e2e_tanh_rom_tb.vvp                       # exhaustive, all 32,769 LUT indices

# full chip through the pads (about 1 min per image in Icarus)
iverilog -g2012 -I rtl -s dla_e2e_chip_tb -o sim/results/dla_e2e_chip_tb.vvp rtl/*.v rtl/dla_e2e_chip.sv tb/dla_e2e_chip_tb.sv
vvp sim/results/dla_e2e_chip_tb.vvp                       # SCLK = clk/4
vvp sim/results/dla_e2e_chip_tb.vvp +HALF=4               # SCLK = clk/8
vvp sim/results/dla_e2e_chip_tb.vvp +IMAGES=2 +ABORT=1    # abort/restart, then back-to-back split-frame images
```
`dla_e2e_chip_tb` also checks the CSR reset values, CSR read/write, err_cmd, the raw DBG path, IO contention and STATUS. It prints the cycle count per image.

### Running a different model or latent
The hardware is model-agnostic for any 64-256-256-784 G300-shaped generator. A new model needs new int8 weights, a new latent and the six requant multipliers. The TB takes all of them as plusargs. With no plusargs it runs the committed MNIST test.

| Plusarg | Meaning | Default |
|---|---|---|
| `+WDIR=<dir>` | `G300_{0,2,4}_{weight,bias}.memh` (int8 hex, row-major [out][in]) | `weights_vh/mnist_gan_mlp` |
| `+ZQ=<file>` | 64 x int8 latent | `tb/data/g300_int8/g300_zq.memh` |
| `+EXPECTED=<file>` | 784 x int8 golden pixels (uint8 ^ 0x80) | `tb/data/g300_int8/g300_int8_rtl.memh` |
| `+STREAM_SRC=<file>` | stream a prebuilt 283,984-B payload instead of building it from WDIR/ZQ | off |
| `+CSR_MEMH=<file>` | 24 bytes: MA0, MB0, MA2, MB2, MW4, MB4 as 32-bit LE. The TB writes them with WR_CSR (0x02, addr 0x10) after the reset-value checks and reads them back before the first START | off (MNIST reset values) |
| `+ACTUAL_MEMH=<file>` | dump the 784 pixels read back over RD_PIX_Q | off |
| `+H2Q=<file>` / `+STREAM_MEMH=<file>` | optional h2 / stream cross-checks | off |

`scripts/gen_e2e_stream.py` builds the host-side files: the stream, plus `csr.memh` from `--csr MA0 MB0 MA2 MB2 MW4 MB4` or `--csr-json`.
```bash
python3 scripts/gen_e2e_stream.py out/m --wdir <wdir> --zq <zq.memh> --csr 243 10590 198 1356 95104071 438503666
vvp sim/results/dla_e2e_chip_tb.vvp +WDIR=<wdir> +ZQ=<zq.memh> +EXPECTED=<golden.memh> \
    +CSR_MEMH=out/m/csr.memh +ACTUAL_MEMH=out/m/pix.memh
```
Without `+CSR_MEMH`, a model with different multipliers fails. For example, the Fashion-MNIST seed 0 gives 256/784 pixels.

### Gate-level simulation (routed netlist)
`scripts/run_e2e_gls.sh [nl|pnl] [-- <plusargs>]` compiles `tb/dla_e2e_chip_tb.sv` with `-DGLS` against the following, then runs it at SCLK = clk/4:
- `librelane/runs/e2e_final/final/{nl,pnl}` (override with `RUN=`);
- the `gf180mcu_as_sc_mcu7t3v3` cell models;
- the behavioral SRAM in `rtl/gf180_sram_1rw_256x8.v`.

`-DGLS` switches the `+H2Q` probe to the flat netlist's escaped instance name. The simulation is zero-delay, and `pnl` adds `-DUSE_POWER_PINS`.

The compiled `.vvp` is reused while it is newer than the netlist and TB. `COMPILE_ONLY=1` compiles once, so several seeds can then run in parallel. All plusargs above apply. One image takes about 30 min in Icarus (33 to 40 min each with 16 runs in parallel).

## Results (2026-10-12)
| | SCLK = clk/4 | SCLK = clk/8 |
|---|---|---|
| clk per image (START, stream, compute tail, 784-pixel readback at clk/8) | 2,347,117 | 4,605,616 |
| ms per image at 25 MHz | 93.9 | 184.2 |
| pixels bit-exact | 784/784 | 784/784 |

After the last stream byte, DONE follows within about 460 clk. Requant and compute are hidden under the stream.

Yosys 0.62 with `gf180mcu_as_sc_mcu7t3v3` tt (SRAMs as blackboxes, same script for both tops) gives:
- `dla_engine_chip`: 323.0 k um^2 synth-level std-cell area;
- `dla_e2e_chip`: 440.0 k um^2, a difference of **+117 k um^2**. The spec estimated +108 k.

OpenSTA on the synth netlist (no wires, no SRAM arcs) gives worst setup slack at 40 ns of +20.9 ns at ss_125C. The old chip gives +20.2 ns with the same method.
